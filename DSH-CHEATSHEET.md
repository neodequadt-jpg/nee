Задача: <одна строка>.
Файл: <точный путь>.
НЕ читай другие файлы — всё в этом промпте.

### API/структуры (готовое, не ищи):
<dataclass / функции / поля — список>

### Требования:
- <invariant 1>
- <invariant 2>

### Верификация (запускаю после тебя):
<команда>

### Артефакт:
EVR-<NNNN>-<slug>.md в ./ (workspace root).
НЕ создавай NEE/. НЕ пиши в ~/NEE/logs/.

Ответ: только код, без объяснений и без research.

## Промпт-шаблон «добавить команду»

Задача: добавить функцию <name> в tg_bot.py.
НЕ читай всё — правки в конкретных местах:
- после `def cmd_stats` — вставить function <name>(chat_id) -> str
- в dispatch() после `if command == "/stats"` — добавить ветку
- в get_welcome_text() — добавить строку
- в get_main_keyboard() — добавить кнопку

### API модулей (готовое):
<import + signature>

### Верификация:
python3 -m py_compile tg_bot.py && pytest tests/test_tg_chat.py -v 2>&1 | tail -3

Ответ: unified diff только правок.

## Антипаттерны (НЕ делать)

- «Прочитай ~/NEE/ARTEM-PRETHEORY.md и предложи дополнения» — dsh выдаст пересказ.
- «Напиши тесты для модуля X, детали смотри в X» — падает на research-фазе.
- «Модуль + тесты + EVR одним вызовом» — упадёт на длине.

## Что делать если упал

1. Первый упал — не повторяй, переформулируй короче.
2. Второй упал — пиши патч Python-скриптом с exact-match anchor.
3. Третий упал — забудь про dsh для этой задачи, только ручной код.

## Где смотреть историю

~/.dsh-orch/history/YYYYMMDD-HHMMSS/
  prompt.txt     — что ушло
  response.txt   — что вернулось (tail-30 обычно достаточно)
  git-before.txt — состояние до
  git-after.txt  — состояние после

## Правило одной строки

Перед любой dshh-командой спроси себя:
  1. Есть ли готовый API в промпте? (если нет — сначала recon)
  2. Один ли файл трогаем? (если нет — разбить)
  3. Как я проверю результат? (если «на глаз» — плохой промпт)

## ARTEM-шаблон промпта (использовать всегда)

```
Задача: <одна строка>.

[REALITY] Сначала проверь:
  <grep -n "def X" file.py>
  <ls path/>

[STEP] Напиши только <file>.

[SPEC] <API, поля, формула — из spec-файла или inline>

[EVIDENCE] После написания запусти:
  python3 -m py_compile <file>
  <pytest | smoke-команда>
  Покажи вывод — не пиши «работает» от себя.

[ARTIFACT] EVR-<NNNN>-<slug>.md в корне workspace.
НЕ создавай NEE/. НЕ коммить.

Ответ: код + вывод верификации, без объяснений.
```

## Три обязательных элемента в каждом dshh

1. REALITY — что проверить перед кодом (grep/ls/curl).
2. EVIDENCE — какую команду запустить после (py_compile/pytest).
3. ARTIFACT — EVR в корне workspace, не в NEE.

Без этих трёх — dsh не следует ARTEM, даже если в system.md написано.
