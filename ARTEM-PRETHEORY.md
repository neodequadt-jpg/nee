# ARTEM Pre-Theory

Операционные правила, выведенные из реальных ошибок (не постулированные).
Ссылки на инциденты: EVR-NNNN, коммиты, даты.
Обновляется, когда новое правило подтверждено ≥1 реальным инцидентом.

Версия: 0.1 (2026-10-12)
Источник: сессия G-0012 (resolver / footbolno)

## E. Egress & Environment

- **E1. Env proxy может быть мёртвым.** `http_proxy=127.0.0.1:8118` может указывать
  на несуществующий процесс. Проверка: `ss -ltnp | grep :8118`. Если пусто — env битый.
  Инцидент: EVR-0015 probe, curl exit 7 на всём через env.

- **E2. `ALL_PROXY=socks://` — невалидная схема для curl.** Нужно `socks5h://`.
  requests подхватит `socks://` как «неизвестный proxy» → exit 7. Для resolver:
  `Session(trust_env=False)` и явный proxy только если нужен.
  Инцидент: EVR-0015 probe.

- **E3. dsh и jail — разный egress.** dsh видит url через свой sandbox (web_fetch),
  jail может не видеть. Не переносить результат dsh-проверки сетевого ресурса
  на прод. Проверять тем же клиентом, что будет в проде (requests.Session).
  Инцидент: footbolno, dsh OK / jail 000.

- **E4. VPS SOCKS5 :1080 не универсален.** Открыт, но footbolno через него → 000.
  Firefox через него ходит (whitelist / exit policy). Прежде чем использовать
  общий прокси для нового источника — probe именно этот источник.
  Инцидент: EVR-0015 probe.

- **E5. WG split-tunnel — только явные префиксы.** `allowed ips` в wg0 —
  список (Telegram, 5.28/5.200, 8.6, 8.47). Нет «0.0.0.0/0». Всё остальное
  идёт direct. Не удивляться, что «через VPS» ≠ «через WG».
  Инцидент: ip route show table all.

## D. Data sources

- **D1. Reality Before Assumptions — буквально.** football-data.org free:
  RPL 404, Nations League 403. iSportsAPI: только 15-day trial. Zafronix:
  требует ключ, RPL не заявлен. **Единственный бесплатный источник с RPL+NL —
  footbolno.ru.** Проверять каталог через API, не по FAQ.
  Инцидент: EVR-0014, EVR-0015.

- **D2. Mojibake: requests без charset → latin-1.** Сервер может не отдавать
  `charset=utf-8` в Content-Type. requests падает на ISO-8859-1,
  русский текст превращается в `Ð¡Ð`. Fix: `r.encoding = 'utf-8'` ПЕРЕД `.text`.
  Инцидент: footbolno CSV, commit e8cdbb7.

- **D3. Матчинг по canonical ID, не по именам.** Даже внутри одной лиги
  `Локомотив Москва` (сигнал) ≠ `Локомотив` (CSV). `Динамо Москва` и
  `Динамо Махачкала` — разные клубы, ambiguous. Матчить по (home_id, away_id,
  date). Имя — только для маппинга signal → id.
  Инцидент: EVR-0016 (96 not_found = 1 матч × 96 снапшотов), commit e8cdbb7.

- **D4. City-suffix strip безопасен только при однозначности.** Отбросить
  последний токен (`Локомотив Москва` → `Локомотив`) можно, только если
  результат мапится на один id. Иначе `Динамо` сколлапсирует в один из двух.
  Инцидент: commit e8cdbb7, `_lookup_unique`.

## C. Cache

- **C1. In-memory кэш без TTL — баг для долгоживущих процессов.** Disk-TTL
  не помогает, если hit уходит из памяти. Каждый уровень кэша — свой TTL.
  Инцидент: bfbd925.

- **C2. Мок `time.time` хрупок.** Глобальный side effect ломает pytest
  (мокается и внутри фреймворка). Альтернатива: физически состарить
  артефакт (meta.json `fetched_at = now - 1000`).
  Инцидент: 22 unit-теста, test_ttl_expiry_refetches.

## A. Agents (dsh)

  уехал в `BET-ANALYZER/NEE/logs/EVR-0015.md` (shadow-путь внутри workspace).

- **A2. dsh sandbox read-only вне workspace.** Нельзя писать в `~/NEE/logs/`,
  симлинки не помогают (sandbox резолвит за пределы). Правило: EVR →
  workspace root, mv руками. Правило зафиксировано в system prompt оркестратора.
  Инцидент: EVR-0013, 0014, 0015, 0016, 0017.

- **A3. Длинные промпты → PI_AI_ERROR (SSE timeout 95s).** Если задача требует
  research + планирование + генерация — dsh валится. Дробить на узкие шаги:
  один шаг = один короткий промпт с готовым input. Если dsh упал 2× подряд
  на одной задаче — писать руками.
  Инцидент: tests/test_footbolno_provider.py — dsh 3× PI_AI_ERROR, написали сами.

## M. Method / инструменты

- **M1. Один длинный heredoc в paste ломается.** Терминал жуёт, часть съедается.
  Дробить на части с маркерами `PART<N>_EOF`, `cat >>` идемпотентен.

- **M2. `re.subn` с `\Z` может съесть соседний блок.** Паттерн `def X():.*?(?=\Z)`
  захватит всё до конца файла, включая следующий class/def. Явные якоря
  (`(?=\nclass |\n\nif __name__)`) безопаснее.
  Инцидент: тестовый файл, потерян CSV_MULTI, восстановлен вручную.

- **M3. Test isolation: свежий инстанс vs тот же объект.** Для проверки
  дискового TTL — новый provider + состаренный meta.json. Проверка in-memory
  TTL — тот же инстанс с `time.time` через `_inmem_ts`. Не смешивать.
  Инцидент: bfbd925 + test_ttl_expiry_refetches.

## A. Agents (dsh) — расширение

- **A5. Готовый spec > research.** Если в промпте есть «прочитай X, найди Y,
  реши Z» — dsh падает на research-фазе (95s SSE timeout). Давай API,
  структуру данных, точную формулу прямо в промпте. Пусть только пишет код.
  Инцидент: test_footbolno 3× PI_AI_ERROR до ручного написания.

- **A6. Один файл = один вызов.** Даже с готовым spec dsh генерит
  один большой файл лучше, чем три средних. Разбивай цепочку:
  fetch → parse → diff → тесты. Каждый шаг отдельным `dshh`.
  Инцидент: bonus_monitor + bonus_tracker одним промптом — уложился,
  но test + test + EVR одним — 2 упало.

- **A7. Верификация после каждого шага.** `py_compile` / `pytest -v` /
  `grep -n` — не давай dsh самому писать «проверено». Пиши верификацию
  в промпте как финальную строку, и ты выполняешь её после dsh.
  Инцидент: dsh писал «COMPILE OK», но regex для __NEXT_DATA__ был неверный.

- **A8. Env верификация перед запуском.** Если задача связана с сетью —
  сначала `env | grep -i proxy` и `curl -v` на endpoint. Не давай dsh
  гадать почему 000. Если задача связана с venv — проверь `which python3`
  и `python3 -c "import requests"` перед dshh.
  Инцидент: 40 минут диагностики WG при причине «мёртвый env-proxy».

- **A9. git status ДО и ПОСЛЕ.** dsh пишет в файлы (иногда не туда, где
  ожидалось). Проверяй: `git status --short` перед запуском (должно быть
  чисто или ожидаемые изменения), после — что появилось.
  Инцидент: EVR-0015 записан в BET-ANALYZER/NEE/logs/, никто не заметил.

- **A10. Не давать dsh коммитить.** Коммиты делает человек после верификации.
  dsh не знает про pre-commit hooks, gitignore динамику, ветки.
  Инцидент: EVR-0022 случайно попал в коммит 5d04e03, потребовался reset.

- **A11. ARTEM в промпте, не в надежде.** dsh не следует ARTEM автоматически.
  Каждый dshh-промпт обязан содержать три строки:
  (1) «Сначала проверь факт: <grep/ls/pytest>», 
  (2) «Напиши только <file>»,
  (3) «Верификация: <точная команда>, покажи вывод».
  Без этого dsh выдаёт «готово» без evidence.
  Инцидент: патч __NEXT_DATA__ regex — dsh отчитался COMPILE OK,
  но regex был неверным, потому что не было проверки на реальный HTML.

- **A13. PATH после активации venv.** `source .venv/bin/activate` может
  затирать пользовательский PATH (если до него `.bashrc` не дочитан или
  есть конфликт). Проверка после активации: `which dshh`. Постоянный фикс:
  добавить `export PATH="$HOME/NEE/bin:$PATH"` в конец `.venv/bin/activate`.
  Инцидент: 3 сброса PATH за сессию 2026-10-12.
